# P24 persisted sources and reconciliation audit

The adapter reads existing immutable domain records and journal effects. It does not post a second journal, materialize payroll, allocate storage revenue by receipt, or mutate financial data. All amounts are signed contributions to profit in integer piastres.

| Category | Persisted origin | Business date | Historical branch | Entry/provenance |
| --- | --- | --- | --- | --- |
| Shipping gross and replacement waiver | `execution.visit_fact` joined to its `operating/shipping` or `operating/waiver` effect | Actual `work_at`, Cairo date | Visit's dispatch/work branch | Immutable effect timestamp, captured price and visit source; replacement incident link preserved |
| Storage revenue | `storage.period.revenue_effect_id` | Whole fee at `start_date` | Period's snapshotted agreement branch | Period/source/effect identities; no receipt or allocation join |
| Salary | Salary earnings in `employees.payroll_period.calculation` | Payroll month start | Frozen earning's captured branch | `frozen_at` is first persistence of the salary earning snapshot; policy source ID and immutable source digest retained |
| Commission | Resolved `execution.earning_basis.journal_effect_id` | Original visit work date | Visit work branch | Historical employee/rate resolution; zero configured commission is valid |
| Additions and entitlement deductions | `employees.payroll_adjustment` plus employee effect | Original `work_date` | Adjustment's historical employee branch | Original classified adjustment and source, not recovery allocations |
| Late commission resolution | `payroll_adjustment.kind=earning_correction` | Original visit/work period | Original work branch | Related visit ID; separate settlement payroll month and later entry retained |
| Paid expenses | `finance.paid_expense` / `paid_cost.effect_id` | Actual payment/business date | Expense's selected branch | Expense/effect/source IDs and recorded timestamp |
| Confirmed compensation and approved employee share | `incidents.confirmation` and its operating effects | Incident confirmation, Cairo date | Confirmed responsible incident branch | Confirmation/source/effect identities; payroll withholding does not recognize another share |
| Linked correcting effects | Recursive ancestry from a classified original | Original classified service/work date | Original historical branch | New recorded timestamp/source/batch and all original effect IDs; signed delta only |

`opening_entitlement`, goods principal, brand payouts, general deposits/withdrawals, treasury movements, employee advances, payroll recovery and salary cash payouts cannot select a profit category. Advance issue/recovery, incident withholding and actual salary cash are a separately labelled payroll explanation. Ordinary expenses exist only when paid; unentered unpaid costs remain outside this report.

A current nonbinding payroll preview is not a persisted salary earning source. An applicable enabled salary without a frozen calculation produces `PAYROLL_NOT_MATERIALIZED`; other known amounts remain available. An omitted period filter checks candidate employed months from employment start through current Cairo month, using dated salary policies and branch history. A recorded-date query does not fabricate a recorded salary from its policy: the frozen salary snapshot supplies that entry time. Missing payroll notices identify candidate work months awaiting processing rather than asserting a recorded earning amount.

Unknown classifications, source/effect mismatches and missing required effects stay explicit. Each invalid duplicated effect identity is excluded in all its copies; unrelated valid effects remain. Known, otherwise valid amounts with missing historical branch are retained in an unattributed company component and are never spread across branches. A branch-filtered read does not disclose an unknown branch's source. Unknown required dates remain issues rather than disappearing behind date predicates.

Current actual money is a separate snapshot section. Account positions require account permission and all the account's configured usage branches in the report scope. Withheld components are null with explanatory notes. Unremitted recipient totals are unknown when any required reported amount is unknown. Storage credit uses receipts minus allocations/refunds, and storage due uses complete charges minus allocations; receipt branch never chooses earned revenue.

Read-only reconciliation compares account cache to money journal, each treasury send/receive phase, signed brand journal to remaining lots/debits, and storage journal to receipt/allocation/refund sources. Findings freeze precise delta, source IDs, observed version, scope and asOf time in the report snapshot. Existing account rebuild, treasury, brand, storage and Settlements paths retain their ordinary permissions. No finding posts money or supplies a generic balance editor.

Connected evidence: `sources.unit.test.ts` covers the 6200 formula, all excluded movement types, salary deductions versus cash, gross/waiver/net, Cairo entry boundaries, correction ancestry, exact integers, duplicate rejection, and incomplete/unattributed data. `reconciliation.db.test.ts` creates genuine service-backed records in an isolated labelled PostgreSQL company. Normal attempted mutations reject immutable guards. Each intentional corruption disables only one named immutable trigger behind a savepoint, observes exact mismatch/missing-source/transit/wallet/storage evidence, then rolls back the source and trigger together. It commits no fake repair or extra cash. The account projection's lawful audited rebuild is separately verified in `profit.db.test.ts`.

The final recorded-window regression uses an actual P21 incident correction, then shifts only its journal entry timestamp inside an isolated savepoint to select it without its original. A one-piastre original-source fault remains visible with its exact delta and prevents counting the descendant correction. The fault timestamp, original amount and immutable guard roll back; this is controlled fault evidence, not a claimed future business event. Native ancestor validation is independent of the ancestor's own recorded-date window.

Source route assertions verify `/storage/:agreementId`, `/expenses/:expenseId` and `/employees/:employeeId/months/:month` from persisted source IDs. Treasury findings link `/treasury/transfers/:id` and require the ordinary `treasury.send` grant; account permission alone exposes only the aggregate explanation. The pre-existing P23 REP-14 adapter in `read-services.ts` still builds `/finance/expenses/:id`, which differs from the ordinary `/expenses/:id` route. That separate catalog report is outside this phase's REP-15 change; every new P24 expense source and finding uses the actual route.

Final independent review also checked frozen-context permission boundaries. Full export creation, recovery and download require both row-source grants and warning/finding grants, including integration recovery even when no computed row requires it. Retrying a prior snapshot command now returns the currently authorized/redacted snapshot rather than raw stored metadata. The connected incomplete-source case revokes integration, retries the exact original command identity, and proves the same snapshot ID and redacted context as an ordinary current read, with source IDs, target, version and recovery path withheld. Account rebuild additionally checks the observed account-version/journal-count pair; two lawful movements whose amounts cancel still invalidate a stale finding.
