# P05 bounded traceability

P05 acceptance is limited to product setup, actual stock receipt, branch inventory reads/history and the reusable shortage/reservation model. The full cross-domain requirements retain their later owners. Evidence is [the verification record](README.md), the connected [database/API tests](../../../tests/db/inventory.test.ts), [quantity/contract examples](../../../tests/unit/inventory.test.ts) and [browser journeys](../../../tests/p05/inventory.spec.ts).

| Assignment | P05 contribution | Later boundary |
| --- | --- | --- |
| ERP-R-049 / ERP-D-046, ERP-D-068 | Stable variants, actual receipts, checked sound/unavailable quantities; no quantity on setup | P07 prepares/reserves real orders; P14 actual returns |
| ERP-R-069 | Separate variant/brand identities and positions; mixed-brand input rejection | Reusable reserve interface is model-tested; real order selection is P07 |
| ERP-R-113 / ERP-D-107, ERP-D-111 | Current stock figures reconcile to immutable movement deltas and source links | Profit, report export and aggregate report formulas belong to P23/P24 |
| ERP-R-127, ERP-R-131 / ERP-D-120, ERP-D-123 | Products/Parcels local switch, search/advanced filters, receipt and variant history, responsive cards | Parcels truthfully empty until P06; journey/custody projections later |
| ERP-R-132 / ERP-D-123 | Assigned physical branch default; explicit external parcel read boundary; no extra stock | Driver/carrier custody and dispatch/transfer effects belong to P13/P15 |
| ERP-R-169 / ERP-D-160 | One existing company brand with branch-tagged stock/movements | Shared wallet/treasury/payout completion remains its respective phases |
| ERP-R-208 / ERP-D-199 | Server-side AND/OR filters, pagination, current-balance movement-date meaning, active chips and query/back preservation | Other screens and export parity remain their owning phases |
| ERP-D-030, ERP-D-041 | Supersession/narrowing respected: product definition is not parcel intake; no extra stored-stock receipt on an order | P06 implements parcel intake; P07 consumes existing stock |
| ERP-D-091 | Caller-owned reserve/release storage and interface, separate from physical on-hand | No real order confirmation or preparation UI in P05 |

Shared and named consuming obligations: ERP-R-019/033 and ERP-D-032 enforce request-time inventory screen/branch scope; ERP-R-071 establishes condition semantics but returns remain P14; ERP-R-128 and ERP-D-120 exclude count sessions/freezes; ERP-R-141 and ERP-D-132 test 5 physical/7 claimed/shortage 2 with all affected active claims held and unrelated variants usable; ERP-R-156 verifies responsive forms; ERP-R-177 and ERP-D-168 retain history/deactivate identities. No commercial source, profit, payment or stock valuation is generated by product setup.

DOM-03 is covered only by the reusable reservation boundary, not a completed order workflow. DOM-18's shortage model is tested; company-wide shipment tracking remains P13. P05-AC-01–08 map to the named tests and captures in README; owner physical-device review remains separate from local browser automation.
