# P23 renderer dependencies and identities

Runtime used for final checks: Node24.21.0/npm12.2.0 via `scripts/use-pinned-runtime.ps1`; disposable native PostgreSQL18.3. New exact API runtime declarations: `exceljs`4.4.0, `playwright`1.63.0 (matching the established test runner), and `@fontsource-variable/cairo`5.3.0 (matching the established web font). Root lockfile is updated only for these required writer/rendering dependencies; no global stack upgrade, SaaS or public storage service.

Read actual upstream documentation and licenses before choosing the writer: [ExcelJS official README](https://github.com/exceljs/exceljs/blob/v4.4.0/README.md), [MIT license](https://github.com/exceljs/exceljs/blob/v4.4.0/LICENSE), [Playwright Page.pdf](https://playwright.dev/docs/api/class-page#page-pdf), [Apache2.0 license](https://github.com/microsoft/playwright/blob/main/LICENSE). Local font package contains the Cairo SIL OFL1.1 license. Copies of runtime licenses/notices are under `licenses/`; installed package license metadata and actual renderer output were inspected. ExcelJS uses explicit strings, RTL views, pageSetup/headerFooter and real OOXML writing; no CSV renaming or Excel input/read service. Playwright is the local network-disabled PDF renderer with Cairo font embedded; production requires its matching Chromium installation (`npx playwright install chromium`, or the explicit executable-path setting).

Initial install used host Node24.19.0/npm11.1.0 and failed strict engine checks, retained [dependency-install.txt](dependency-install.txt). The targeted install rerun passed with `--engine-strict=false` before the existing pinned helper was selected for all final scripts; [dependency-install-rerun.txt](dependency-install-rerun.txt). No claim that the host's default runtime changed. [font-dependency.txt](font-dependency.txt) records the font reuse. Current lock and migration identities are recorded in `artifact-identities.json` after final generation.

[dependency-audit.json](dependency-audit.json) records two moderate findings, zero high/critical: ExcelJS's transitive uuid bounds issue affects v3/v5/v6 supplied-buffer paths. The pinned ExcelJS source uses uuid v4 for workbook internals; P23 writes only controlled workbook structures and does not expose spreadsheet intake. This bounded path assessment is not a clean-audit claim or a blanket safety assertion. The offered downgrade to ExcelJS3.4.0 was not applied as an unrelated/older writer replacement.

Artifacts store exact decimal money as **text** because Excel's numeric precision cannot represent every PostgreSQL bigint minor amount. Source sheets retain integer minors and source IDs; totals use independently reconciled immutable snapshot strings, not workbook formulas. Formula-like user strings are protected even for consumers that import string cells. The report registry and future P24 interface do not infer revenue from positive cash movements.
