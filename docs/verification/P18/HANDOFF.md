# P18 interfaces and boundaries

Native implementation dated 2026-10-06. It reuses the P03 command/journal kernel, the single P17 brand wallet (`BrandWalletService.postCompensation`), the P08 historical employee resolver and period guard, P05/P15 custody facts and the P14 typed disposition path. There is no second wallet, no cached balance, no separate cash repayment and no backfill for existing shipments.

## Implemented paths

- `packages/database/migrations/0022_p18_incidents.sql` (the prompt planned `0018`; the next free number after P17's `0021` was used). Schema `incidents`: `incident` (reported/confirmed/dismissed, custody and responsible branch, holder/driver snapshot, immutable report), `affected_source` (materialized per-source lock row), `affected_item` (range allocation per source with a GiST exclusion over `int8range(unit_offset, unit_offset+quantity)` while not released — two *different* incidents cannot claim one unit), `shipment_hold`, `confirmation` (value, compensation, shares, responsible branch, employee payroll branch/month, lot and obligation links), `disposition` / `disposition_attempt`, `replacement`, `review` and `command_outcome`. `employees.incident_obligation` is the typed original employee debt. Deferred constraint triggers prove the complete confirmation effect set at commit and that a waiver in a price snapshot has an incident-linked company-funded replacement. Journal classification gains operating `employee_compensation_share`; `returns.intent` uniqueness widens to `(command_record_id, request_id)` so one incident can address several exact return requests. Capability `incidents` (`/incidents`, assigned policy) is registered.
- `packages/domain/src/incidents/`: `validateIncidentShares` (value ≥ compensation > 0, nonnegative shares summing exactly, warehouse loss cannot charge an employee, employee/month required only for a positive employee share).
- `packages/database/src/incidents/`: `incidentCandidate` (actual custody capacity per shipment line, stock movement or in-transit loose transfer line; never derives value from recipient due), `incidentSourceKey`, `assertNoIncidentHold`.
- `packages/contracts/src/incidents/`: closed schemas/validators/OpenAPI for `GET/POST /api/v1/incidents`, `GET /catalog`, `GET /candidates`, `GET /commands/{commandId}`, `GET /{id}`, `POST /{id}/confirmation-preview`, `POST /{id}/confirm`, `POST /{id}/dismiss`, `POST /{id}/review`, `POST /{id}/disposition`. `ShipmentFields.replacement` (`incidentId`, `payer: recipient|brand|company`, `reason`) and `ShipmentPrice.waiverMinor/incidentAgreement` extend ordinary intake; there is no employee payer.
- `apps/api/src/modules/incidents/service.ts`: `incidentCommands` (families `incident.report/confirm/dismiss/review/disposition`), `incidentDetail`, `incidentList`, `incidentPreview`, `incidentCandidates`, `incidentCatalog`; `replacement.service.ts`: `authorizeReplacement`, `recordReplacement`, `replacementWaiver`; `http.ts` routes with CSRF/origin, closed bodies and no query on writes.
- Holds added to existing services: ordinary shipment edit/dispatch/transfer/transfer-receipt/stock condition change/return receipt reject `INCIDENT_CUSTODY_HELD` for quantities reserved by an unresolved incident.
- The retained immutable shipment hold is inactive after dismissal. Ordinary correction/actual transfer receipt may then proceed under their existing custody rules; any other reported/confirmed incident still blocks them. Dismissal does not create a receipt or restore stock condition. Replaying a previously rejected operation retains its original result; a deliberate operation after the state change uses a new command ID.
- `apps/web/src/features/incidents/`: `/incidents` (list + frequent/advanced filters), `/incidents/new` (report), `/incidents/:id` (review, confirmation preview, confirmed effects, disposition status, replacement links, dismissal/review). Replacement entry extends the ordinary `/shipments/new` form; tracking shows an operational `incident.reported` milestone only.

## Command boundaries

| Command | Locks (in order) | Effects |
| --- | --- | --- |
| `incident.report` | integration source row → `affected:<sourceKey>` rows (sorted) → transfer manifests → shipments → stock positions | Incident, affected allocations, shipment holds, sound branch stock moved to unavailable (hold). **No** wallet, journal, obligation or money effect. |
| `incident.confirm` | source rows → incident → manifests/shipments → P14 return request (driver-held, when the documented operation is permitted) → stock positions → brand wallet → employee company/employee/period guard | One P03 source batch: brand `compensation` (eligible lot) + operating `cost` (−compensation) and, for an employee share, employee `obligation` + operating `employee_compensation_share`, all at the responsible branch and observed effective date; `employees.incident_obligation`; disposition rows; confirmation. No money movement. Duplicate command → retained result; second incident on the same units → exclusion/409. |
| `incident.dismiss` | as confirm (no wallet) | Reason recorded, allocations released; no money. |
| `incident.review` | incident → brand wallet | Linked P21 review row and a source-specific hold on the unpaid remainder of the compensation lot; paid allocations and the original confirmation stay unchanged. |
| `incident.disposition` | incident → manifests/shipments → return request | Follow-up when the documented P14 disposition becomes available after confirmation; queues the exact affected subset once with a stable action identity. |

## Replacement and waiver

`authorizeReplacement` requires a confirmed incident of the same brand without an open review, assigned scope and the `incidents` grant; client `recipientShippingDue` is never waiver authority. For `payer='company'` the price keeps the standard tariff, sets recipient and brand shipping to zero and records `waiverMinor = tariffMinor`; goods due is unchanged (250 goods + 50 shipping → recipient total 250). The agreement snapshot is immutable (`REPLACEMENT_AGREEMENT_IMMUTABLE`). `replacementWaiver` feeds the existing P12 `dispatchPrice`, so the canonical snapshot carries `shippingDue` 0 and the actual goods `unitDue`; the existing P13 visit posting adds fee + equal waiver + normal commission once per eligible visit.
