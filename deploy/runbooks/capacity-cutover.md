# Capacity, alerts and later cutover

No production cutover is authorized. Do not claim readiness from the local build or P22's tiny fixture timings.

## Required bounded capacity trial

Use an isolated company/batch and the implemented native services to seed about55000 shipments over a year, multiple lines/attempts, three branches and ten drivers. Exercise15 concurrent authorized staff, inbox/source application and real XLSX/PDF exports. Record hardware, database/worker/connection limits, indexes/EXPLAIN plans, client/network, warmup and dataset counts. Measure list/detail p95<=500ms, local money/stock command p95<=800ms excluding explicit remote waits, and cached-route navigation<=1second on the measured browser/network. Ramp higher until a measured limit is found; preserve every failure and compare money/custody/inbox/action invariants before/after. Never truncate V1 modules or substitute a generic framework benchmark.

Deploy the same digest/configuration contract into a second distinct network/host layout, restore/move the test data, and compare native counts/source identities. A second container on the same host is a network-layout test, not independent-host/offsite failure-domain evidence. Current runtime/compiler tests do not implement or prove this workload; it remains a required checkpoint after the release/issuer/integration prerequisites are available.

| Signal | Operator action |

| Expired leases/retry age/unknown source age | Existing `/integration` and `/integration/recovery`; recover original command/action under the current grant, never generate replacement money intent |
| Oldest unapplied inbox event/known gap | Scoped P22 replay/reconcile review; dependent wallet/custody stays held |
| Database locks/deadlocks/connections | Inspect pg_stat_activity/pg_locks/pg_stat_database; bound worker lanes/pools and retain original IDs on retry |
| Invariant discrepancy | Existing `/settlements` and REP-15 source findings; no untyped balance edit |
| Export age/load | Existing `/reports` durable export status; independent bounded export lane, current authorization before download |
| Restore/read-only mode | Arabic global banner and `/api/v1/operations`; company operator reviews external evidence and reconciliation before a reviewed redeploy |

Configure the actual monitoring destination without buying an unselected subscription. This table is an alert-routing specification; only signals with actual emitted/observed test evidence may be called verified.

## Separate production instruction checklist

1. Confirm ownership/access, approved company/issuer/public integration scope, reviewed external Tawsel gates, full isolated P25 evidence and capacity on the intended host. Measure actual spare KVM2 capacity beside Tawsel; local WSL RAM is not VPS capacity.
2. Verify remote encrypted backup credentials/permissions/retrieval/decryption/retention and independently recoverable keys/issuer/configuration. Record a current backup/checkpoint.
3. Review release digest/schema/config version, forward repair/compatibility and the paused-outbound restore reconciliation result. Resolve every lost/uncertain cash/stock action using external evidence and typed flows.
4. Obtain the explicit instruction for this exact production host/traffic/DNS window. Define the named operator who can close/reopen money and integrations, monitoring coverage and measured recovery recommendation.
5. Execute the approved cutover, then verify same-origin TLS/Secure cookies, local readiness, issuer login/logout/grant revocation, authorized native queries and original-action integration outcomes. Watch all defined alerts and preserve checkpoints.
6. If invariant/access/schema/recovery evidence disagrees, close consequential admissions again and follow the reviewed forward repair/isolated restore path. Do not force-push, perform destructive down migrations or invent cash reversals.
