## 3. Native and canonical authority

The request remains an offer. Goods remain with the driver until accepted actual subset receipt or a legitimate disposition. Staff receive at the **original customer-dispatch source branch**, not whichever branch is convenient. Multi-branch staff select among assigned branches with the receipt-screen grant. Record the actual native staff actor in ERP audit; the source service command uses its documented integration identity and does not claim to be that human in a closed envelope.

Use `return.listPending`: GET `/api/v1/erp/returns/pending` with required `driverId` and `sourceBranchId`, following cursor pages up to 100. Use `return.getNativeRequest`: GET `/api/v1/erp/returns/requests/{requestId}` for current quantities/revisions. Recover a source return command with `return.getNativeResult`: GET `/api/v1/erp/returns/actions/{actionId}`. A first page or a pending result is not proof that all returns are clear.

For actual receipt call POST `/api/v1/erp/returns/commands/return.confirmSubsetReceipt`, capability `return.receive`, concrete `ReceiveCommand`. Payload is `requestId`, `receivingBranchId`, nonempty `items`, each `{itemId, expectedRevision, quantity}`. Quantities are whole integers from 1 to 1,000,000; revision is the documented nonnegative safe integer. Reject duplicate item keys, zero, fraction, excess, wrong branch, stale revision or incompatible lifecycle. Use current item revisions, not one generic request timestamp. There is no invented fixed return quota; enforce real transport/schema bounds.

For legitimate loss/damage disposition use POST `/api/v1/erp/returns/commands/return.recordDisposition`, capability `return.dispose`, concrete `DisposeCommand`, the same subset identity fields and `disposition` of `lost` or `damaged`. Apply only a separately recorded legitimate custody/incident decision; the integration action itself does not approve brand compensation, deduct an employee, create usable goods or make a physical receipt. P18 will add the full incident workflow through this typed interface. Do not add an arbitrary driver outcome editor to the return screen.

Each accepted `Transition` has unique `transitionId` and task/cycle/outcome/source-line/source-reference/source-cycle/branch/quantity/revision/action-time evidence. Normalize response and `return.subsetReceived`/`return.dispositionRecorded` to the same native transition. Handle `return.requested` explicitly through the P13 ordered worker. Preserve original request, cumulative item state and transition history. A later duplicate event, result lookup, replay or snapshot must not add the quantity twice.

## 4. Inventory, condition and transaction boundaries

For a source line/cycle enforce dispatched = delivered + driver-held + branch-received + lost + damaged. `returnRequired` is a subset of held custody, not an extra additive bucket. For each request enforce requested = received + unresolved + lost + damaged. Do not treat an unresolved remainder as automatically lost, delivered or received. A legitimate received subset can proceed independently; no general all-returns-cleared gate is added.

Before authoritative remote acceptance, keep a physical observation as pending/quarantined evidence unavailable to dispatch, transfer or brand handover. Show both facts honestly: staff recorded physical arrival, Tawsel confirmation is pending. Persist native command, item revision snapshot, observed condition and outbox atomically. Send HTTP outside the PostgreSQL transaction. A timeout keeps the observation unavailable and recovers the same `actionId`; never replace it with a new receipt command. Definite rejection preserves the observation for review and reread rather than silently erasing physical evidence.

After accepted transition, use one local `UnitOfWork` to append its unique fact, move custody, post condition-specific stock, record audit, settle the intent and mark the event applied if processing an event. Sound stored-stock pieces become available after actual receipt/inspection; damaged or uncertain stock is unavailable. Externally supplied whole parcels retain parcel identity and never create loose SKU stock. Receiving a sealed parcel checks identity and exterior, not unseen internal contents. A suspected internal shortage becomes an incident candidate, not automatic compensation.

Lock request/item and shipment/cycle before sorted `(branch, brand, variant)` stock positions, following the shared global order. Lock/update existing positions correctly; an absent row must be inserted safely before a lock can protect it. Uniqueness belongs on company/source/transition identity as well as native command identity. Add additive migrations for `return_receipt`, lines, pending physical observation, disposition linkage and explicit receipt allocation to later cycles. Existing historical items with uncertain condition remain unavailable until actual review; never infer reusable quantity merely from a delivered status or return offer.

Concurrent receipt, disposition, permitted driver correction, whole retry and redispatch must respect the winning canonical item/lifecycle revision. If one wins, the other displays its definite conflict and refreshed facts; it does not silently retry modified payload under one action. P13 correction handling retains history and cannot rewrite an accepted physical stock movement. Do not claim a local SQL transaction makes Tawsel atomic with ERP.

## 5. Receipt-funded redispatch and brand handover

Use POST `/api/v1/intake/commands/dispatch.createFromReceipt`, capability `assignment.manage`, `RedispatchCommand`. The payload includes stable `externalId`, `previousDispatchCycleId` and a complete explicit fresh `snapshot`. Preserve the commercial shipment reference, previous cycles, source line identity and captured commercial pricing; create a new source/canonical cycle, never reopen the old attempt. Calculate exact current recipient obligation through P12's serializer and existing payer rules. Do not assume a generic whole retry can deliver the rejected portion of a partial outcome.

Allocate only compatible, actually accepted, sound, unallocated returned quantities. Unreceived, lost, damaged, already allocated or physically transferred-away stock cannot fund the action. Reserve receipt allocation and native goods/cover under one command transaction, persist the immutable outbox and follow P12 uncertainty handling. Query GET `/api/v1/intake/cycles` with scoped `externalId` and all cursor pages, retaining historical cycles. A lost redispatch response never permits another cycle to consume the same receipt twice.

Keep CHECK-003 dependent customer dispatch disabled for the two unresolved cases: an already accepted A source moving to B before departure, and an accepted return at A moving to B before a fresh customer cycle. Required evidence is a documented allowed public sequence, expected source/assignment/item revisions, line compatibility and receipt allocation, original/new return branch, positive A-to-B result and rejection/retry cases. No fake receipt at B, direct driver endpoint, departed snapshot rewrite or replacement commercial ID is allowed. The rest of the return desk and same-branch redispatch can reach verified-within-scope status.

Native return-to-brand is a separate actual handover action. Require branch-held available parcel/pieces, permitted branch/screen, exact brand/recipient identity and quantities, actor and recorded time. Lock against redispatch/transfer, consume custody once and retain the movement trail. Do not call a nonexistent Tawsel brand-return endpoint. Planned pickup, cancellation or return offer is not handover. No automatic brand payment or invoice follows; commercial consequences use their own approved journals/workflows.
