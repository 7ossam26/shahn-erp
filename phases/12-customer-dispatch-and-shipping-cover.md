## 3. Rules and exact canonical mapping

First submit a customer execution snapshot when staff prepare the order for customer dispatch, using the actual dispatch branch. Local order registration and packing can continue during a Tawsel outage. Existing accepted-source branch changes and returned A-to-B redispatch remain TAWSEL-CHECK-003; a `sourceBranchExternalId` property does not prove arbitrary branch mutation. Keep affected dispatch blocked with a precise explanation and retain the original shipment identity. Never manufacture another commercial order to evade the restriction.

Persist a native dispatch intent and customer cycle before sending. Keep desired, pending and accepted source revisions separately. Human shipment references contain digits; native UUIDs, canonical task UUIDs, source external IDs and `sourceDispatchCycleId` remain distinct. Each remote command has a stable `actionId` linked to the native `commandId`. A single native journey can create multiple separately identified remote actions.

Build only the closed `SourceSnapshot` fields: `externalId`, `sourceDispatchCycleId`, `sourceRevision`, `expectedSourceRevision`, `sourceBranchExternalId`, `recipientName`, `recipientPhone`, `destination`, `splittingAllowed`, `allocation`, `lines`, `shippingDue`, `totalDue`, `priority` and the documented optional `sourceOrderReference`, `earliestAt`, `instructions`. `allocation` is exactly `exact-outstanding-per-unit`. Initial expected source revision is zero; subsequent revisions use actual accepted authority and lifecycle.

Enforce recipient name 1–200 characters, address text 1–500, 1–100 lines, each stable `sourceLineId`, description 1–200, integer quantity 1–1,000,000 and exact `unitDue`. Phone validation after explicit display normalization is `^(?:\+[1-9][0-9]{7,14}|01[0125][0-9]{8})$`. Preserve invalid input for correction; do not invent digits. Optional brand reference is at most 256 and instructions at most 1,000 characters. Render the explicit inspection choice and separate comment into clear instructions; the wire has no `inspectionAllowed`. Keep a supplied map link native; use confirmed-pin coordinates only with actual confirmed, bounded coordinates. A URL is not evidence of a confirmed pin.

Native money is EGP integer-string `amountMinor`, stored as bigint. Wire money is nonnegative safe integer Number `amountMinor`, `currency:"EGP"`, `exponent:2`. Validate every product and sum before conversion; maximum safe wire integer is 9007199254740991. `totalDue = sum(quantity × unitDue) + shippingDue`. Never use floating-point rounding to repair invalid money. Distinct outstanding amounts per piece require distinct stable lines. `splittingAllowed` permits eligible whole-piece partial delivery; it never divides one shipment across two simultaneous drivers.

Keep commercial tariff, packing uplift, payer, goods value and recipient outstanding obligation distinct. Goods 100 + goods 150 + shipping 50 means wire total 300. Goods prepaid to the brand means goods due 0 and shipping due 50. Both prepaid to the brand means explicit zero recipient obligation; the ordinary eligible visit still creates the selected brand shipping debit later. D195 excludes the different earlier-recipient-attempt-payment scenario. For D203 incident-linked company-funded replacement, goods still due 250 plus waived shipping 50 means wire goods 250, shipping 0, total 250. Retain tariff 50, waiver 50 and commission policy natively. Do not zero goods without a separate actual prepaid-goods fact or add unsupported payer/waiver wire fields.

Use POST `/api/v1/intake/commands/intake.submitSnapshot` (`SourceSnapshotCommand`, `intake.prepare` capability), then `intake.prepare` (`PrepareCommand`) and `assignment.receiveBatch` (`ReceiveBatchCommand`, `assignment.manage`). Preparation identifies driver and references without asserting receipt. Actual receipt adds `receiptAsserted:true`. Each `AssignmentReference` has `externalId`, `sourceDispatchCycleId`, `expectedSourceRevision`, `expectedAssignmentRevision`, `assignmentRevision`. Follow exact closed concrete schemas, including source context; do not insert a human actor into a service envelope.

Use `assignment.withdraw` and `assignment.reassignBeforeDeparture` only within supported predeparture lifecycle and physical truth. Protected departed data, prices, assignment and outcomes cannot be overridden by any ERP admin. Do not add remote cancellation, driver outcome or route controls. Keep `intake.setUrgencyBeforeDeparture` as conditional adapter/conformance support: expose no new urgency UI or automatic write unless an existing selected ERP action has explicit scope evidence. The endpoint alone does not select that product action. Capacity is 50 remaining planned stops including branch stops, not a daily quota. A batch that would move 49 to 51 rejects atomically.

## 4. Transactions, unknown results and migration

Add dispatch-intent, snapshot-revision, accepted assignment mapping and immutable price/cover references through additive SQL migrations. Reuse existing shipment and reservation tables. Index company/branch/status and canonical identity; retain unique native command, source action and shipment-cycle identities. Existing orders remain locally registered or explicitly unsynchronized; do not backfill accepted source revisions from a boolean or pretend goods were handed over.

Under one P03 `UnitOfWork`, recheck current screen permission, assigned source branch, shipment version, complete packing, sound allocated quantity, no competing transfer, ready identities and wallet gate. Lock shipment/reservations and the single company-brand wallet in the documented global order. Commit immutable handover intent, required shipping cover, native audit and outbox together. The public HTTP call happens after commit. Retain unavailable goods and the pending intent until authoritative response resolves it. A physical handover acknowledgement timeout must not restore stock or permit another driver to receive the same parcel.

For a nonnegative brand, negative signed entitlement blocks new handover. Known brand-paid shipping must also fit eligible credit after debits, affected holds and existing cover. Pending unremitted goods, storage credit and another brand's balance are not cover. Given eligible 100 and pending 500, cover 60 leaves 40 eligible to pay; pending 500 alone does not fund cover 60. The normal recipient-funded tariff does not require a full brand reservation. Company-waived shipping has zero brand exposure, while the existing-debt gate remains applicable. Allow-negative brands bypass this commercial cover restriction; they do not gain fictitious cash for payouts. Existing cover is deducted once.

Consume a reservation into the earned brand fee once in P13. Release unused cover only from an authorized actual lifecycle transition, such as legitimate predeparture cancellation/unassignment or actual return without a chargeable visit. A retry, stale display, timeout or route-planning failure cannot release it. Never reserve an unlimited number of possible future visits.

Recover via GET `/api/v1/intake/results/{actionId}` and scoped `intake.getTask`/`intake.listTasks`. Pending 202 remains pending; an unknown response resends the same immutable action or reads its result. A definite stale rejection requires reread and a new reviewed native intent, not changed JSON under the old action. Lease fencing prevents a late worker overwriting the current result. Accepted assignment remains accepted if later planning fails. Result/event echoes share semantic acceptance identities to avoid double local custody effects.
